# 제타 관심도 관측소

상태: 승인
기준일: 2026-09-23

## 목표

- 대상 사용자: 제타의 플랫폼 관심도와 인기 콘텐츠 변화를 투자 관점에서 추적하는 사용자
- 10초 안에 얻을 결론: 최근 선택 기간 동안 제타 전체 관심도가 증가했는가
- 결론 뒤의 행동: 증가에 기여한 태그를 확인하고 개별 플롯까지 내려가 원인을 검증함
- 한 문장 목표: 공개 원값과 Wayback 복원값으로 플랫폼 → 태그 → 플롯의 대화량 추이를 설명함

## 확정 범위

### 이번에 함

- 전체 공개 플롯·전체 태그를 향해 반복 확장하는 재개 가능한 전수 수집
- 재생성 제외 대화량 `interactionCount`를 대표 지표로 사용
- 재생성 포함 대화량 `interactionCountWithRegen` 별도 수집
- 원댓글+답글 합산 댓글 수
- 공개 플롯 수·신규 플롯 수·활성 플롯 비율
- 태그별·플롯별 7일·30일·60일·직접 기간 변화
- 매일 00:10 KST 기준 일 1회 수집
- Wayback 구형 `/characters/{id}/profile`과 신형 `/plots/{id}/profile` 동시 복구
- Wayback 한국 홈 캡처의 공개 플롯 원값 복원과 동일 플롯 매칭 성장지수
- Wayback에 보관된 구형 캐릭터·신형 플롯 API JSON의 `interactionCount` 복원
- 플롯명·제작자·태그 검색 후 개별 플롯의 실제 누적 대화 시계열 조회
- 첫 수집부터 읽기 전용 웹 대시보드 공개

### 이번엔 안 함

- 설정집 분석
- 댓글 언어·국가 분석
- 댓글 감성 분석
- 좋아요: 안정적인 익명 세션 수집이 확인될 때 추가
- 임의 종합 인기점수
- 결측일 보간

## 화면 구조

```text
[헤더: 마지막 수집·확보 범위]
[기간: 7일 | 30일 | 60일 | 직접 설정]
[KPI: 총 신규 대화 | 플롯당 신규 대화 | 활성 플롯 | 공개 플롯]
[단일 시계열: 지표 토글, 실제 관측일 표식]
[플롯별 시계열: 검색 | 선택 | Wayback·현재 API 원값]
[급상승 태그 상위 10]
[급상승 플롯 상위 10]
[플롯 상세: 정확한 원값과 관측 시계열]
[수집 범위·오류·출처]
```

## 지표 규칙

- 플랫폼 총량은 날짜별 고유 플롯 ID 최신 관측값을 한 번씩만 합산함.
- `플롯당 신규 대화`는 두 시점 모두 값이 있는 동일 플롯의 증가량 평균임.
- 초대형 플롯 편향 검사를 위해 중앙값도 계산하되 기본 화면에는 보조값으로 둠.
- 태그 인기도는 해당 플롯 증가량 전부를 각 태그에 표시함.
- 태그의 플랫폼 기여도는 플롯 증가량을 해당 플롯의 태그 수로 나눠 배분함.
- 삭제·비공개 전환 플롯은 현재 공개 총량에서 제외하고 사라진 플롯 수로 별도 기록함.
- 카드 숫자는 만·억 단위, 툴팁과 표는 1회 단위 원값을 표시함.

## 차트 규칙

- 모든 원천을 같은 표식과 선으로 표시하며 Wayback·현재를 시각적으로 구분하지 않음.
- 과거 기본 프록시는 캡처별 단순 합계가 아니라 동일 플롯이 10개 이상 겹치는 두 캡처의 개별 증가 배수 중앙값을 연결한 지수로 둠(첫 관측일=100).
- 성장지수의 마지막 점은 가장 가까운 비교 가능한 Wayback 홈 표본과 최신 공개 API 관측에서 동일 플롯 10개 이상을 다시 매칭해 최신 수집일까지 연결함.
- 홈 노출 합계·평균·중앙값·상위 10 합계는 표본 구성 변화의 영향을 받으므로 보조 원값 레이어로만 제공함.
- 홈 캡처는 플랫폼 전수가 아니라 공개 표본이며, 복원 날짜 수·색인 캡처 수·캡처당 플롯 수를 차트에 함께 표시함.
- 값이 있는 날짜에만 동일한 원형 표식을 표시함.
- 데이터 없는 날짜에는 표식을 만들지 않고 가장 가까운 관측점끼리 연결함.
- 중간 날짜 값을 생성하지 않으며 툴팁도 실제 관측점에서만 열림.
- 플롯별 차트는 홈 HTML·과거 API JSON·현재 API에서 같은 `plot_id`로 확인된 원값을 날짜별로 병합함.
- 안내 문구: `표식 = 값이 확인된 날 · 선은 관측값 연결`.

## 수집 규칙

- GitHub Actions 기준 매일 00:10 KST(전날 15:10 UTC)에 실행함.
- 모든 관측에 실제 `observed_at`을 보존함.
- 같은 KST 날짜 재실행은 기존 날짜 값을 갱신함.
- 한 원천 실패가 다른 원천 저장을 막지 않음.
- 초기 전수조사는 랭킹·디스커버리·추천에서 시드 플롯을 모으고, 발견한 태그 검색을 끝까지 순회하며 새 태그를 다시 큐에 넣는 방식으로 확장함.
- 실행시간 제한을 넘지 않도록 페이지 예산을 두고 다음 실행에서 이어감.

## 상태 처리

- 로딩: 스켈레톤 대신 짧은 `데이터 불러오는 중` 표시
- 빈 데이터: 아직 기준선이 없다고 설명하고 임의 판정하지 않음
- 오래된 데이터: 마지막 정상 수집 시각과 경과시간 표시
- 부분 실패: 성공 지표는 보여주고 실패 지표와 오류만 별도 표시
- 초기 조사: 확보 고유 플롯 수·태그 수·댓글 커버리지·남은 태그 큐 표시

## 디자인 다이얼

- DESIGN_VARIANCE: 4 — Muse 관측소의 검증된 카드·차트 구조 재사용
- MOTION_INTENSITY: 2 — 차트 전환 외 모션 최소화
- VISUAL_DENSITY: 7 — 첫 화면은 4개 KPI와 한 개 차트, 표는 하단에 배치

## 성공 기준

- 수집기 1회 실행으로 랭킹·디스커버리·태그 시드가 SQLite에 저장됨.
- 같은 날짜 재실행 시 중복 관측 행이 생기지 않음.
- 대화량 두 정의와 댓글 수가 1회 단위로 검산됨.
- 대시보드가 실제 관측일에만 표식을 표시함.
- 기간 선택이 KPI·차트·태그·플롯 표에 동시에 적용됨.
- 첫 수집부터 커버리지와 오류를 숨기지 않음.
